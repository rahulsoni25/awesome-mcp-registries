# Contributing / Hướng dẫn đóng góp

Thanks for helping grow this list. Quality over quantity. / Cảm ơn bạn đã đóng góp. Chất hơn lượng.

## Rules / Quy tắc

1. **The destination must be real and the link must work (HTTP 200).** No dead links, no placeholder or "coming soon" pages.
   *Điểm đến phải có thật, link còn sống (HTTP 200). Không link chết, không trang "sắp có".*
2. **It must genuinely be a place to publish, list, or submit an MCP server** — an official registry, an auto-indexing directory, a submission-based registry, an awesome list, or a client gallery.
   *Phải thật sự là nơi để xuất bản/niêm yết/nộp một MCP server.*
3. **Prefer the canonical source:** the official site, the GitHub repo, or the official docs. Avoid mirrors or forks when a first-party source exists.
   *Ưu tiên nguồn chính: trang chính thức, repo GitHub, hoặc tài liệu chính thức.*
4. **One item per pull request**, added to the correct section, in a logical order.
   *Mỗi PR một mục, đúng nhóm, thứ tự hợp lý.*
5. **Bilingual.** Add the entry to both `README.md` (English) and `README.vi.md` (Vietnamese).
   *Song ngữ — thêm vào cả hai file README.*
6. Keep the description **factual and one line**, and note **how to submit** (web form, CLI, GitHub connect, PR).
   *Mô tả đúng sự thật, một dòng, kèm cách nộp (form web, CLI, kết nối GitHub, PR).*

## Entry format / Định dạng

```markdown
- [Name](https://canonical-url) — One factual sentence describing what it is and how to submit.
```

## Checklist

- [ ] The destination is real and is a place to publish/list/submit an MCP server
- [ ] Link returns HTTP 200 and is the canonical source
- [ ] Description is factual, one line, and notes how to submit
- [ ] Added to both `README.md` and `README.vi.md`, in the right section
